### 1. Recurring listings (fixed)
- **Change.** A row now counts only on the days it happens. `parseRecurrence` reads weekly patterns ("Every Tuesday", "Fri & Sat", "Tue-Thu and Sundays", "Second Thursday of the month") and listed dates ("Nov 13-15 and 19-21", "vs. Jaguars Sun Nov 22"). If the recurrence line just says "Weekly", weekdays are taken from the time line.
- **Ranking** is by fit, not start date: keyword score, then one-off events ahead of weekly nights, closeness, and a penalty for happy hour, trivia, bingo, karaoke and open mic unless asked for. At most two rows per venue. Default limit stays 8; `more_not_shown` says how many were cut.

A related word found only in passing in a description does not count.
- **One search, both sides.** `search_events` returns up to 3 matching `places`; `search_places` returns up to 3 `upcoming_events`. Places also inherit the tags of events held there (`happening_here`).
- **New hints.** `music` (genre) and `crowd` (ages, singles, seniors, teens, wheelchair accessible...). Results carry a `crowd` field only when the row's own tags say who it is for.

## Risks and regressions to watch
- **Behavior changes MCP clients will see.** `town` can now return nearby towns (marked); `confirmed_this_year` appears only when false; new fields added; `category` no longer filters when a keyword is given.
- **Time parsing can be wrong on messy text.** One venue's hours read as closing at 11pm where the text is ambiguous. A wrongly dropped event is still visible under `already_over_today`. "Weekends" is read as Fri-Sun and flagged for the agent to confirm.
- **`open_now` uses the real clock** even when the person states a different time; only `search_events` takes `after`.
- **Lexical noise remains.** "run" still returns a band called Running With Scissors and a dog run.
- **Unsupported colour seen twice:** "Pet Santa nights usually pop up closer to December" (dog-owner) and "about 5 minutes from both of you" for two towns (girls-night).
- **The digest's unsuggested rows are thin** (date, time, cost). The prompt tells the agent to say only what is on the line. In toddler turn 3 the agent recommended the library petting zoo from the digest without searching and called it "indoors", which I could not trace to a listed field.
- **Memory guard false positives.** A legitimate fact containing a word like "mom" or "birthday" is refused.
- **Gap tickets depend on wording.** Only 1 of 31 replies in the 10-scenario run matched the miss pattern, so softer misses ("I can't confirm a single brewery...") are not ticketed.
- **A short, complete-looking preamble** (40+ characters) sent with only a save call would go out as the reply. Not seen.
- **Duplicate rows in the data.** Freestyle Flashback now exists twice in `events`; `searchEvents` hides same-venue same-day twins, but research should merge them.

## New risks from round 2
- **Town from text can be wrong** for someone asking about a town they don't live in ("anything near Ridgewood?"). It only applies when no town is saved, and the agent can overwrite it.
- **A cut-off reply loses its tail** (often the backup pick or the closing question), and a save call that would have followed the text is lost with it.
- **The stall retry costs a second model call** on the rare turn it fires.
- **`requirements` can pick up a sentence that is a detail rather than a condition** (for example "designed for kids ages 2 to 12").
- **Output shape changed again for MCP clients:** `places` on an event search and `upcoming_events` on a place search are now objects with a `note` and a list.
